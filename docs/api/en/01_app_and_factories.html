classSlim\App#

  • Source File: Slim/App.php
  • Namespace: Slim
  • Extends: Slim\Routing\RouteCollectorProxy (which implements RouteCollectorProxyInterface)
  • Implements: Psr\Http\Server\RequestHandlerInterface
  • Template Annotation: @template TContainerInterface of (ContainerInterface|null)

Slim\App is the central application kernel in Slim 4. By extending RouteCollectorProxy, it exposes all route registration methods (get(), post(), put(), delete(), options(), patch(), any(), map(), group(), redirect()) directly on $app, while implementing PSR-15's RequestHandlerInterface so the entire application can be composed inside outer PSR-15 runners or invoked directly in tests via $app->handle($request).

Usage Example (Slim\App)#

<?php

declare(strict_types=1);

use Psr\Http\Message\ResponseInterface as Response;
use Psr\Http\Message\ServerRequestInterface as Request;
use Slim\Factory\AppFactory;

$app = AppFactory::create();

// 1. Parse JSON / form / XML request bodies
$app->addBodyParsingMiddleware();

// 2. Explicit routing middleware (placed before custom middlewares that inspect RouteContext)
$app->addRoutingMiddleware();

// 3. Outermost error middleware (added last -> executed first in LIFO order)
$errorMiddleware = $app->addErrorMiddleware(true, true, true);

$app->get('/health', function (Request $request, Response $response): Response {
    $payload = json_encode(['status' => 'ok', 'slim' => $this::VERSION], JSON_THROW_ON_ERROR);
    $response->getBody()->write($payload);
    return $response->withHeader('Content-Type', 'application/json');
});

$app->run();

classSlim\Factory\AppFactory#

  • Source File: Slim/Factory/AppFactory.php
  • Namespace: Slim\Factory

AppFactory is a static builder class that constructs Slim\App instances without requiring manual instantiation of a ResponseFactoryInterface. When AppFactory::create() or AppFactory::createFromContainer($container) is called, it either uses a pre-configured ResponseFactoryInterface, resolves one from the PSR-11 container, or queries Psr17FactoryProvider to auto-detect an installed PSR-17 implementation (and automatically decorates it with Slim\Http\Factory\DecoratedResponseFactory if slim/http is installed and $slimHttpDecoratorsAutomaticDetectionEnabled is true).

classSlim\Factory\ServerRequestCreatorFactory#

  • Source File: Slim/Factory/ServerRequestCreatorFactory.php
  • Namespace: Slim\Factory

ServerRequestCreatorFactory is the static counterpart to AppFactory for incoming HTTP requests. Called automatically by App::run() when no ServerRequestInterface is passed, it probes Psr17FactoryProvider to locate a vendor ServerRequestCreatorInterface capable of building a PSR-7 ServerRequestInterface from PHP superglobals, and optionally wraps it in SlimHttpServerRequestCreator if slim/http is present.

classSlim\CallableResolver#

  • Source File: Slim/CallableResolver.php
  • Namespace: Slim
  • Modifiers: final class
  • Implements: Slim\Interfaces\AdvancedCallableResolverInterface (which extends CallableResolverInterface)
  • Template Annotation: @template TContainerInterface of (ContainerInterface|null)

CallableResolver translates Slim's flexible callable notations into executable PHP callables. It supports:

  1. Native PHP callables (Closure, function names, invokable objects, [$object, 'method']).
  2. [ClassName::class, 'method'] two-element arrays (normalized to 'ClassName:method').
  3. Slim colon notation 'ClassName:method' matched by CallableResolver::$callablePattern (!^([^\:]+)\:([a-zA-Z_\x7f-\xff][a-zA-Z0-9_\x7f-\xff]*)$!).
  4. Container service IDs or class names: resolved from $this->container->get($class) if registered in the PSR-11 container, or instantiated via new $class($this->container) otherwise.
  5. Automatic default method selection: resolveRoute() defaults RequestHandlerInterface instances to 'handle', resolveMiddleware() defaults MiddlewareInterface instances to 'process', and resolve() defaults to '__invoke'.
  6. Closure binding: if $this->container is present and the resolved callable is a Closure, it binds $this inside the closure via $callable->bindTo($this->container).

classSlim\MiddlewareDispatcher#

  • Source File: Slim/MiddlewareDispatcher.php
  • Namespace: Slim
  • Implements: Slim\Interfaces\MiddlewareDispatcherInterface (which extends Psr\Http\Server\RequestHandlerInterface)
  • Template Annotation: @template TContainerInterface of (ContainerInterface|null)

MiddlewareDispatcher implements Slim 4's concentric LIFO (Last-In, First-Out) middleware stack. It wraps a core RequestHandlerInterface $kernel (RouteRunner at the application level, or Route at the route level) in lightweight anonymous RequestHandlerInterface decorators. Every call to add(), addMiddleware(), addDeferred(), or addCallable() replaces $this->tip with a new outer handler pointing $next to the previous $this->tip.

    public function addMiddleware(MiddlewareInterface $middleware): MiddlewareDispatcherInterface;

    public function addCallable(callable $middleware): self;
}

use Psr\Http\Message\ResponseInterface as Response;

classSlim\ResponseEmitter#

  • Source File: Slim/ResponseEmitter.php
  • Namespace: Slim

ResponseEmitter streams a PSR-7 ResponseInterface to the PHP SAPI output buffer. It includes three important HTTP edge-case safeguards:

  1. Multi-Value Set-Cookie Preservation: In emitHeaders(), all headers replace previous values on their first iteration ($first = true) except set-cookie (strtolower($name) !== 'set-cookie'), ensuring multiple Set-Cookie headers are never overwritten.
  2. Status Line Emitted After Headers: emitStatusLine() is deliberately called after emitHeaders() to prevent PHP's built-in header('Location: ...') behavior from overriding an explicit custom redirect status code (e.g., 301, 303, 307, 308) with 302 (Slim issue #1730).
  3. Empty Status & Chunked Streaming: isResponseEmpty() suppresses body output on 204 No Content, 205 Reset Content, and 304 Not Modified (or empty streams), while emitBody() streams bodies in $responseChunkSize (4096-byte) chunks and halts early if connection_status() !== CONNECTION_NORMAL.

classSlim\Logger#

  • Source File: Slim/Logger.php
  • Namespace: Slim
  • Extends: Psr\Log\AbstractLogger (which implements Psr\Log\LoggerInterface)

Slim\Logger is the zero-configuration fallback PSR-3 logger instantiated by ErrorHandler when no custom Psr\Log\LoggerInterface is provided to App::addErrorMiddleware() or ErrorMiddleware::__construct(). It inherits emergency(), alert(), critical(), error(), warning(), notice(), info(), and debug() from Psr\Log\AbstractLogger and delegates all levels to error_log((string) $message).
